"
State machine behaviour:

There are 3 states: off, on, emergency.
There are 4 events: turn_on, turn_off, danger, mitigate

The machine updates the state in a fixed interval, with initial state 'off'.

- In state off, when turn_on is active, and danger is not active, the system should go to 'on'.
- In any state, when danger is active, the system should go to 'emergency'.
- In state 'emergency', when danger is not active, and mitigate is active, the system should go to 'off'.
- In state 'on', when turn_off is active and danger is not active, the system should go to 'off'.
- A state change only occurs when one of the above conditions are met

The structure below allows us to verify invariants on this state machine:
Given a starting state, can we enter a state that is undesirable?

The state at time t is a function: the unknowns state(t, s) state that the machine is in state s at time t, and
active(t, e) states that event e is active at time t. The solver chooses the state and events at time T0.
The next state is defined by the transition rules, and the property is checked for every interpretation of
state(T1, _) that follows from T0.

Run with:
    rsbdd examples/state_machine.txt -t
"

is_state(Off) -> true;
is_state(On) -> true;
is_state(Emergency) -> true;

"The machine is in exactly one state at time t"
sum t # valid(t) -> exists s # is_state(s) & state(t, s) & forall s2 # is_state(s2) & state(t, s2) => s2 = s;

"next(t, s): s is the state after time t. The state only changes when one of the conditions is met"
sum t, s # next(t, s) ->
    if active(t, Danger) then s = Emergency
    else if state(t, Off) & active(t, TurnOn) then s = On
    else if state(t, On) & active(t, TurnOff) then s = Off
    else if state(t, Emergency) & active(t, Mitigate) then s = Off
    else state(t, s);

sum t, u # step(t, u) -> forall s # is_state(s) => (state(u, s) <=> next(t, s));

"Every possible next state satisfies the property: if the machine is on and no turn_off event is active, it remains on"
forall state(T1, _) # valid(T0) & valid(T1) & step(T0, T1) =>
    (state(T0, On) & -active(T0, TurnOff) => state(T1, On))

"
Result:
The property is satisfiable in every situation except the following: state=on & event=danger.
In this situation the next state will be 'emergency' and not 'on', so the property is not satisfied.

| True           | Any           | Any                  | Any                | Any                | Any                 | Any                  | True  |
"
